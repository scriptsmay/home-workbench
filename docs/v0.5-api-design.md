# v0.5 账号体系打通：API 契约与数据模型（v0.4 增补）

> 在 `docs/v0.4-api-design.md` 基础上增补。v0.4 的函数拓扑、认证方案（scrypt + HMAC token）、CORS 策略、错误结构全部沿用。
> v0.5 新增：身份映射层（`hw_identities`）、一次性绑定码（`hw_bind_codes`）、绑定合并 `bindMerge`、冲突 diff 与裁决、小程序 `wx.cloud.callFunction` 通道。

## 0. 总览

```
小程序 ──wx.cloud.callFunction(hwSyncApi, { action })──┐
                                                       ├──> hwSyncApi（同一函数，双入口）
Web    ──HTTPS /api/*（HTTP 网关）────────────────────┘
                 ├─ hw_identities   身份映射（wx:<openid> → canonical uid）
                 ├─ hw_bind_codes   一次性绑定码
                 ├─ home_users      账号（既有，canonical uid 的来源）
                 ├─ home_items      业务数据（统一 _id == uid）
                 └─ home_push_log   内容变化快照（既有，新增 kind 扩展）
```

- **Web 侧鉴权**：`Authorization: Bearer <token>`（不变）。
- **小程序侧鉴权**：不使用 token。云函数内 `cloud.getWXContext().OPENID` 可信获取，再查 `hw_identities` 解析 canonical uid；未绑定则使用临时身份 `wx_<openid>`。
- **同一业务逻辑**：`pull` / `push` / `bindMerge` 在两个入口共用同一 handler。

## 1. 身份模型

### 1.1 `hw_identities`（新增）

```json
{
  "_id": "<自动>",
  "identity": "wx:<openid>",
  "provider": "wechat",
  "openid": "<openid>",
  "uid": "<canonical uid>",
  "tempUid": "wx_<openid>",
  "status": "linked",
  "mergePending": false,
  "nickname": "string|null",
  "createdAt": "<ISO>",
  "linkedAt": "<ISO>",
  "mergedAt": "<ISO|null>"
}
```

- 唯一索引：`identity` 升序。
- 解绑 = 删除该映射记录（`home_items` 中 canonical uid 的数据不动）；小程序回到临时身份 `wx_<openid>`，其数据保留在自己名下。
- Web 账号本身是 canonical 身份，**不**写入本表；本表只存「微信 → Web 账号」的映射。

### 1.2 `hw_bind_codes`（新增）

```json
{
  "_id": "<自动>",
  "code": "6位数字",
  "uid": "<生成者 canonical uid>",
  "expiresAt": "<ISO>",
  "usedAt": "<ISO|null>",
  "attempts": 0,
  "createdAt": "<ISO>"
}
```

- 唯一索引：`code`。
- 约束：单次有效；单账号未核销并发码 ≤ 3；错误尝试 ≥ 5 次作废；过期码由兑换时惰性清理 + 定时清理。

### 1.3 `home_items` 文档形态统一（迁移）

- Web 既有形态：`_id == uid`。小程序既有文档为随机 `_id` + `where({uid})` 读写，两端事实上不通。
- **目标形态（唯一）**：`_id == 身份uid`，`uid` 字段与 `_id` 一致；`data` 为全量业务 state；`updatedAt`；`prevData/prevUpdatedAt` 仅由服务端 push 维护。
- 临时身份的 uid 即 `wx_<openid>`，其文档 `_id` 同样等于该 uid。
- 存量迁移（一次性、幂等，管理端脚本）：对每个小程序文档，按 `uid` 归并为 `_id == uid` 的新文档（多条则先做并集合并），旧文档标记 `migratedFrom: <旧_id>`、`migratedAt`，不再参与读写。
- `prevData` 为服务端内部字段：任何客户端读写路径都不得将其当业务数据返回或合并。

## 2. 绑定合并 `bindMerge`

与 `mergeFields`（字段级 LWW + 数组整键替换）**不同**，绑定合并是「两个不同身份文档」的合并：

| 数据 | 规则 |
|---|---|
| `items` / `wants` / `logs` | 按条目 id（`_id`/`id`）做 **union + 去重**：仅单侧存在的条目直接保留（无损）；同 id 但内容不同的条目 → **真冲突** |
| `shopName` / `tagline` | 相同则取值；不同 → 真冲突（默认较新 `updatedAt` 侧胜出） |
| `members` / `cats` / `places` | 并集（保持原顺序，新值追加在后） |
| `freshDays` / `soonDays` | 同标量字段规则 |
| `schemaVersion` | 取较大值 |
| `updatedAt` / `ui` / 服务端内部字段 | 不参与合并（结果取服务器时间） |

- 合并结果写入 canonical uid 文档（`_id == uid`），并做 `prevData` 深备份。
- 快照：`home_push_log` 记录 `kind: 'bind_merge'`（自动合并）/ `kind: 'bind_merge_manual'`（含用户裁决），记录双方业务指纹与结果指纹，供倒查与回滚。
- 临时身份文档**不删除**，标记 `mergedInto: <canonical uid>`、`mergedAt`，便于核对与回滚。
- 幂等：已建立映射且无 `mergePending` 时重复绑定直接返回当前 uid，不重复合并。

## 3. 冲突 diff 结构（`conflicts[]`）

冲突预检与裁决共用同一结构。约定：**left = canonical（Web 账号）侧，right = 临时（小程序）侧**。

```json
{
  "conflictId": "c1",
  "kind": "entry",
  "collection": "items",
  "entryId": "<条目id>",
  "field": "shopName",
  "left": { "value": {}, "updatedAt": "<ISO>" },
  "right": { "value": {}, "updatedAt": "<ISO>" }
}
```

- `entry` 冲突的 `value` 为条目全文；`scalar` 冲突的 `value` 为标量值。
- **仅真冲突进入 diff**；仅单侧存在的条目属无损并集，不进入 diff、不可被排除。
- 冲突 diff 一次性生成并随「合并票据」返回；票据过期后重新预检。

## 4. 合并票据（merge ticket）

- 结构：`{ k: 'merge', identityId, uid, tempUid, exp }`，HMAC 签名（复用 `HW_TOKEN_SECRET`），TTL 15 分钟。
- 用途：客户端持票提交裁决，服务端凭票定位「哪一次合并」，**不信任客户端自报的数据**；合并所需数据全部来自服务端已存的两侧文档。
- 裁决提交：

```json
{
  "ticket": "<merge ticket>",
  "choices": [
    { "conflictId": "c1", "side": "left" },
    { "conflictId": "c2", "side": "right" }
  ]
}
```

- 未出现在 `choices` 中的冲突项按「较新 `updatedAt`」默认裁决（写入契约，前端提示可修改默认）。
- 提交后：执行合并 → 清 `mergePending` → 返回合并后全量数据。

## 5. HTTP 端点（Web 侧，Bearer）

| 端点 | 请求 | 响应 |
|---|---|---|
| `POST /api/bind/code` | `{}` | `{ ok, code, expiresAt }`（6 位数字，5 分钟） |
| `POST /api/bind/identities` | `{}` | `{ ok, identities: [{ identityId, identity, nickname, status, mergePending, linkedAt }] }` |
| `POST /api/bind/revoke` | `{ identityId }` | `{ ok }`（解绑后小程序回到临时身份，其数据保留在 `wx_<openid>` 文档） |
| `POST /api/bind/merge/pending` | `{}` | `{ ok, items: [{ identityId, tempUid, ticket, conflicts, generatedAt }] }` |
| `POST /api/bind/merge/apply` | `{ identityId, ticket, choices }` | `{ ok, data, updatedAt }` |

- 限频：`bind/code` 每 uid 每 10 分钟最多 3 次成功生成（并发未核销码 ≤ 3）。
- `revoke` 仅对 `identity` 前缀 `wx:` 的映射有效。

## 6. callFunction actions（小程序侧，`event.action`）

`wx.cloud.callFunction({ name: 'hwSyncApi', data: { action: '...', ... } })`；响应统一 `{ ok, ... }` 或 `{ error: { code, message } }`。

| action | 请求（除 action 外） | 鉴权 | 响应 |
|---|---|---|---|
| `ping` | — | — | `{ ok, authed: true, appid }`（验证通道与 OPENID 可用） |
| `mpLogin` | — | OPENID | `{ ok, bound, uid?, tempUid, nickname? }`（已绑定直接免登录） |
| `mpLoginPassword` | `{ username, password }` | OPENID | `{ ok, uid, username, mergeRequired, ticket?, conflicts? }`；口令校验复用 `/api/auth/login` 逻辑（含失败锁定） |
| `bind` | `{ code }` | OPENID | 同 `mpLoginPassword`（兑换绑定码路径） |
| `mpMergeStatus` | — | OPENID | `{ ok, mergeRequired, ticket?, conflicts? }`（恢复被打断的合并） |
| `mpMergeApply` | `{ ticket, choices }` | OPENID | `{ ok, data, updatedAt }` |
| `pull` | — | OPENID → uid | `{ ok, data, updatedAt }`（与 HTTP pull 同 handler） |
| `push` | `{ data, updatedAt }` | OPENID → uid | `{ ok, data, updatedAt, strippedEmptyPush? }`（与 HTTP push 同 handler） |

- `mpLoginPassword` / `bind` 成功即写 `hw_identities`；若临时身份文档存在数据，则**先建映射并置 `mergePending: true`**，返回冲突 diff 与票据，由用户在「合并数据」页裁决后 `mpMergeApply`；无临时数据则直接 `bound` 且无需合并。
- **小程序侧不签发、不使用 token**：业务请求身份一律由服务端 `OPENID` 解析。

## 7. 错误码表（v0.5 增补，沿用 `{ error: { code, message } }` 结构）

| HTTP | code | 语义 |
|---|---|---|
| 400 | `bind_code_invalid` | 绑定码不存在 / 已作废（错误次数超限） |
| 400 | `bind_code_expired` | 绑定码过期 |
| 400 | `bind_code_used` | 绑定码已被使用 |
| 400 | `merge_ticket_invalid` | 合并票据缺失 / 验签失败 / 过期 / 与身份不匹配 |
| 400 | `identity_required` | 缺少 `identityId` 或身份不属于当前用户 |
| 401 | `invalid_credentials` | 用户名或口令不正确（泛化） |
| 401 | `unauthorized` | 缺 token / 验签失败 / 过期 / 已吊销 |
| 403 | `identity_taken` | 该微信身份已绑定其他账号 |
| 429 | `too_many_requests` | 口令锁定中 / 触发限频 |
| 404 | `not_found` | 未知路由或 action |
| 500 | `internal` | 未预期错误 |

## 8. 环境变量（无新增）

`HW_TOKEN_SECRET`（同时用于 merge ticket 签名）、`TCB_ENV`、`HW_ALLOWED_ORIGINS`。

## 9. 部署与迁移清单

1. 创建集合 `hw_identities`（`identity` 唯一索引）、`hw_bind_codes`（`code` 唯一索引）。
2. 部署 `hwSyncApi` 新版本（含双入口与新增路由）。
3. 运行存量迁移脚本（小程序随机 `_id` 文档 → `_id == uid`，幂等）。
4. 收紧集合权限：`home_items` / `home_users` / `hw_identities` / `hw_bind_codes` 客户端读写关闭，仅云函数访问（旧版小程序直连写入将失败，属预期过渡行为）。
5. 小程序发版必须在服务端上线并完成验收之后。
